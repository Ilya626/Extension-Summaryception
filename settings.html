Where to Place Memory

Memory is your saved story summaries. Choose where the chat model reads them in its next request. Before: Memory → System / setup → … → Chat
Before the conversation: System / setup → … → Memory → Chat
After the conversation: System / setup → … → Chat → Memory
Chat means your messages and the AI's replies. The dots stand for other preset blocks, such as character details or lore.
1 = before the latest message; 2 = before the latest two messages. Each user or AI message counts separately; excluded messages do not count. 0 switches to After the conversation.
Changes the memory's message role, not its position. System is the usual choice for story memory.
ST details and ordering limits Immediately before the conversation places memory directly before the first retained chat message, after the setup and prefix instructions preceding it. It follows that boundary when ST trims older messages. The former After system/setup option now uses this placement automatically. Inside / After the conversation use ST's In-chat @ Depth; After is depth 0. Your preset still controls its other blocks. Other extensions or final preset instructions can still follow the memory: ST has no native “always last in the full request” position. During Text Completion Continue, ST puts depth 0 before the AI message being continued.

Message Context (Ghosting)

Uses ST's native Exclude from prompts / Include in prompts controls (/hide and /unhide). Messages stay readable. Manual choices are preserved. Uncheck both types for fully manual control. Off by default. When checked, the next successful new batch can overwrite manual inclusion/exclusion, including earlier summarized messages. Changing settings, switching chats, refreshing, importing, and regenerating a snippet do not reapply ghosting.

World Info for Summarization

Scans all prior memory + the selected passage using ST's connected lorebooks and WI rules/budget. Includes all WI positions for new summaries, layer compression and regeneration. Lore is reference, not recorded events. Separate from ordinary chat World Info Scanning above.
English by default. Applies to every summary request, including compression and Refine. Auto leaves the language to your prompt and source. Existing memories change language only when regenerated or refined.

Summarizer Connection
Choose which LLM connection to use for summarization. Use a cheaper/faster model to save costs while keeping your main API for RP. One mode for all connections, including Regenerate, Refine, layer transfers and Test Connection. Off: wait for one complete response. On: receive response chunks. Off by default.

Raw Context and Blind Zone

Keep at least this many source tokens outside the blind zone. Both user and assistant text count through ST's tokenizer. Whole exchanges are kept; the actual tail can be larger.
Automatic generation waits for this many older eligible tokens. A batch uses whole exchanges up to this budget; a single oversized exchange is sent whole. Prior summaries, WI and instructions are additional. Force Summarize can process a smaller remainder.
Default: 1 user/assistant exchange. Excluded before token counting, triggers and source selection, including Force Summarize. Automatic ghosting cannot hide this zone, even with Reapply enabled. Manual hiding is preserved. A trailing unanswered user message is also protected.

Memory Token Budgets

Five layers share this budget as x, x/divisor, x/divisor², x/divisor³, x/divisor⁴. Oldest summaries move when their layer exceeds its token budget.
Default: 2. Provider output tokens are saved with each summary and never recounted after a model change. If usage is unavailable, a one-time estimate is marked.
New summaries are saved before checking layer overflow. Transfers use original L0 texts with the normal summarization prompt and no forced output size. If a transfer fails or L4 is full, processing stops with a warning; the new summary remains saved.
